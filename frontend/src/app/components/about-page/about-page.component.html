About This Demo

Purpose

Reads a file of heart rate observations (tuples: heart rate, datetime) for a given patient and transforms them into FHIR R4 resources, demonstrating the difference between Batch and Transaction Bundles.

Data Input

The file name is derived from the patient identifier (dashes removed) with a .txt extension. Each line contains a tuple: 

(heart_rate, "ISO-8601 datetime")

For example, patient 356-444-9972 reads from 3564449972.txt.

FHIR Transformation

Each tuple is converted into a FHIR HeartRateObservation resource with:

  • LOINC code 8867-4 (Heart rate)
  • Category: vital-signs
  • Custom extension: http://mobilemonitor.com/heartrate

Bundle Strategy

The system checks whether the patient already has a FHIR server ID:

Patient Has FHIR ID → Batch Bundle

The patient already exists on the server. The bundle contains observations only, each referencing the patient by their known server ID. Entries are processed independently.

No FHIR ID → Transaction Bundle

The patient does not yet exist on the server. The bundle includes a new Patient resource plus all observations, linked via urn:uuid references. The entire bundle is processed atomically.

Demo Workflow

  1. Select a patient from the list
  2. Optionally post the patient to the FHIR server (this determines bundle type)
  3. Click Generate from File to load heart rate data
  4. Click Build Bundle — the system auto-selects Batch or Transaction
  5. Click Post Bundle to submit to the FHIR server
  6. View the assigned FHIR IDs in the Results panel
