# 3.2: Create Dashboard Shell with Material Toolbar and Workflow-Stage Sections

**Story ID:** 3.2
**Epic:** 3 — Angular App Shell & Dashboard Layout
**Slug:** dashboard-layout
**Status:** ready-for-dev

## Story

**As an** instructor
**I want** a dashboard layout with a Material toolbar and distinct sections for each workflow stage (Patients, Observations, Bundle, Results)
**so that** I can click through the FHIR demo in a logical, visually organized flow.

---

## Acceptance Criteria — LOCKED

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. The AppComponent template includes a Material toolbar (`<mat-toolbar>`) with the app title "FHIR Training Demo".

3. Each section is wrapped in a Material card (`<mat-card>`) with a card title (`<mat-card-title>`).
4. Sections are laid out in a responsive grid using Tailwind CSS utility classes (e.g., `grid`, `grid-cols-1`, `md:grid-cols-2`, `gap-4`).
5. The layout renders correctly in Chrome and Firefox at desktop resolutions (1280px and above).
6. Placeholder text is shown in each section (e.g., "Patient list will appear here") to indicate where content will be inserted in future stories.
7. The AppComponent TypeScript class is minimal — no logic, just the component decorator and empty class body (all section content is static placeholders for now).

## Dev Notes — LOCKED

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

### Architecture Context

This story implements the dashboard layout shell described in FR-013: "The frontend is organized as a dashboard with visually distinct panels/sections for each workflow stage: Patients, Observations, Bundle, Post/Results." [Source: prd.md#FR-013]

The layout establishes the visual structure that all subsequent Epic 4, 5, and 6 stories will populate with interactive components. The four sections map directly to the workflow stages the instructor will demonstrate. [Source: prd.md#FR-013]

### Dashboard Workflow Stages (FR-013)

The four sections correspond to the FHIR Bundle lifecycle demo workflow:

1. **Patients:** Select a patient from the edge gateway (Epic 4 stories)
2. **Observations:** Generate heart rate observations for the selected patient (Epic 5 stories)
3. **Bundle:** Construct a FHIR Bundle (Batch or Transaction) and preview JSON (Epic 5 stories)
4. **Results:** Post the bundle to the FHIR server and display assigned IDs (Epic 6 stories)

[Source: prd.md#FR-013, prd.md#Goals and Objectives UG-2]

### Material Toolbar and Cards (ADR-006)

**Toolbar:** Use `<mat-toolbar color="primary">` for a branded header with the app title. This provides a consistent, professional look aligned with Material Design. [Source: architecture.md ADR-006]

**Cards:** Each workflow stage section is wrapped in a `<mat-card>` for visual separation and hierarchy. Material cards provide built-in padding, shadows, and header/content structure (`<mat-card-title>`, `<mat-card-content>`). [Source: architecture.md ADR-006]

Import the required Material modules:
```typescript
import { MatToolbarModule } from '@angular/material/toolbar';
import { MatCardModule } from '@angular/material/card';
```

Add these to the `imports` array in `app.module.ts` (or if using standalone components, to the component's imports). [Source: architecture.md ADR-006]

### Tailwind Grid Layout (ADR-006)

Use Tailwind's utility classes for responsive layout instead of custom CSS. This aligns with ADR-006: "Tailwind utility classes preferred over custom CSS." [Source: architecture.md ADR-006]

**Grid structure:**
- `grid`: Establishes a CSS grid container
- `grid-cols-1`: One column on mobile/small screens
- `md:grid-cols-2`: Two columns on medium+ screens (≥768px)
- `gap-4`: 1rem spacing between grid items
- `p-4`: 1rem padding around the grid container

At desktop resolutions (1280px+), the layout will show a 2x2 grid. On smaller screens, it stacks vertically (single column). [Source: architecture.md ADR-006]

**Why this layout:** The 2x2 grid at desktop resolution keeps all workflow stages visible simultaneously, allowing the instructor to see the full demo flow on one screen. [Inference based on NFR-003 usability requirement]

### NFR Coverage

**NFR-003 (Usability for Live Demo):** The dashboard layout supports the "≤ 10 clicks for full lifecycle" requirement by organizing all workflow stages in a single view. The instructor never needs to navigate between pages. [Source: prd.md#NFR-003, architecture.md#7-fr--nfr-coverage-matrix]

**NFR-005 (Browser Compatibility):** Angular Material and Tailwind CSS both support current Chrome and Firefox. No browser-specific CSS or polyfills are required for the layout. [Source: prd.md#NFR-005]

### Component Design (Architecture §4)

The AppComponent is the "shell" component described in `architecture.md#4-component-design`: "AppComponent (shell: toolbar + dashboard layout)". It is purely presentational in this story — no logic, no state. Future stories will add routed or nested components inside the card sections. [Source: architecture.md#4-component-design]

### Placeholder Text (AC #6)

Each section contains placeholder text to indicate its future purpose. This allows verification that the layout is correct before implementing the actual feature components. The placeholders will be replaced in Epic 4-6 stories with:
- **Patients:** `<app-patient-list>` and `<app-patient-detail>` (Epic 4)
- **Observations:** `<app-observation-panel>` (Epic 5)
- **Bundle:** `<app-bundle-panel>` (Epic 5)
- **Results:** `<app-results-panel>` (Epic 6)

[Inference based on architecture.md component overview]

### Styling Approach

**Prefer Tailwind utilities** for all spacing, layout, and color classes. Only write custom CSS in `app.component.css` if a specific style cannot be achieved with Tailwind (unlikely for this story). [Source: architecture.md ADR-006]

If the Material theme color conflicts with the desired toolbar color, override using Tailwind text/background utilities (e.g., `bg-indigo-600 text-white`), but prefer using Material's `color="primary"` attribute first. [Inference]

### Responsive Breakpoints

Tailwind's default breakpoints:
- `sm`: 640px
- `md`: 768px (this is the breakpoint we use)
- `lg`: 1024px
- `xl`: 1280px

Testing at 1280px+ (AC #5) ensures the 2x2 grid is visible. Below 768px, the grid collapses to a single column (stacked sections). [Source: Tailwind documentation, AC #5]

### Strategy

**Unit tests (minimal):** AppComponent has no logic to test. The auto-generated `app.component.spec.ts` should verify the component compiles. Optionally add a shallow test to check that the title "FHIR Training Demo" is rendered.

**Visual verification (manual):**
- Start `ng serve` and open `http://localhost:4200` in Chrome at 1280px+ resolution
- Verify:
  - Toolbar is visible at the top with title "FHIR Training Demo"
  - Four cards are visible in a 2x2 grid
  - Each card has a title (Patients, Observations, Bundle, Results) and placeholder text
  - Cards have adequate spacing (gap between them)
- Repeat in Firefox at 1280px+ resolution

**Responsive test (manual):**
- Resize browser window to 767px (just below `md` breakpoint)
- Verify: Cards stack vertically in a single column
- Resize back to 1280px+
- Verify: Cards return to 2x2 grid

**No e2e tests for this story** — no interactive behavior yet, just layout.

### Edge Cases

- **Material theme not applied:** If the toolbar and cards render without Material styling (flat, no colors), verify that a Material theme is imported in `styles.css` (e.g., `@import '@angular/material/prebuilt-themes/indigo-pink.css';`). This should have been set up in story 3.1.
- **Tailwind classes not applied:** If grid layout does not work, verify Tailwind is correctly configured in `tailwind.config.js` (scanning `./src/**/*.{html,ts}`) and that Tailwind directives are in `styles.css`. This should also have been set up in story 3.1.
- **Content overflow:** If placeholder text is very long, verify that `<mat-card-content>` allows scrolling or wraps text. Material cards handle this by default, but test with longer placeholder strings if needed.
