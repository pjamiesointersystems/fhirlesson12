## Dev Notes — LOCKED

### Architecture Context

This story creates the foundational Angular frontend structure that all subsequent UI stories depend on. The project is the "frontend" half of the two-tier client-server architecture described in `architecture.md#2-architecture-pattern` [Source: architecture.md#2-architecture-pattern].

### Frontend Stack Requirements

**Angular Material:** Required by project constraints [Source: prd.md#Executive Summary]. Use a prebuilt Material theme (Indigo/Pink, Deep Purple/Amber, or Pink/Blue-Grey) to minimize custom theming. Material components will be used for buttons, cards, tables, and toolbars in later stories. [Source: architecture.md#8-technology-stack]

**Tailwind CSS:** Also required by project constraints [Source: prd.md#Executive Summary]. Configure Tailwind to coexist with Angular Material — Tailwind utilities are for layout, spacing, and custom styling; Material components provide the UI widgets. Tailwind's reset may conflict with Material — if issues arise, scope Tailwind's base reset or apply selectively. [Source: architecture.md ADR-006]

### Proxy Configuration (ADR-007)

The Angular dev server and FastAPI backend run on different ports (4200 and 8000 respectively). To avoid CORS issues during development, use Angular's proxy configuration to forward all `/api/*` requests from the dev server to `http://localhost:8000`. This allows the frontend to use relative URLs (`/api/patients` instead of `http://localhost:8000/api/patients`). [Source: architecture.md ADR-007]

**proxy.conf.json structure:**
```json
{
  "/api": {
    "target": "http://localhost:8000",
    "secure": false
  }
}
```

Reference this in `angular.json` under `projects.frontend.architect.serve.options.proxyConfig`. [Source: architecture.md ADR-007]

The backend also configures CORS middleware as a fallback, allowing `http://localhost:4200` as an origin. [Source: architecture.md ADR-007]

### ApiService Design (ADR-001, ADR-005)

The ApiService is a centralized HTTP client service that wraps all backend API calls. Every method should:
- Use relative URLs starting with `/api/` (the proxy forwards them) [Source: architecture.md ADR-007]
- Return typed Observables wrapping the ApiResponse envelope [Source: architecture.md ADR-005]
- Include the session_id as a query parameter for all POST endpoints (injected from SessionService) [Source: architecture.md ADR-004]

**Stub methods for this story (full implementation in later stories):**
- `getPatients(): Observable<ApiResponse>` — GET /api/patients
- `getPatient(identifier: string): Observable<ApiResponse>` — GET /api/patients/{identifier}
- `postPatient(identifier: string, sessionId: string): Observable<ApiResponse>` — POST /api/patients/{identifier}/post?session_id={sessionId}

[Source: architecture.md#6-api-specifications, ADR-001]

### SessionService Design (ADR-004)

The backend maintains server-side session state, keyed by a session_id UUID. The frontend must generate a session_id on app initialization and include it in all API requests that mutate state. [Source: architecture.md ADR-004]

The SessionService should:
- Generate a UUID on construction (use `crypto.randomUUID()` if available in the target browser environment, or install the `uuid` npm package for broader compatibility)
- Store the session_id as a private property
- Expose `getSessionId(): string` method

Later stories will inject SessionService into ApiService and automatically append the session_id to relevant API calls. [Source: architecture.md ADR-004]

### ApiResponse Envelope (ADR-005)

All backend API responses use a standardized JSON envelope to enable consistent error handling across all endpoints. [Source: architecture.md ADR-005]

**Success shape:**
```typescript
{
  success: true,
  data: { ... },
  message?: string
}
```

**Error shape:**
```typescript
{
  success: false,
  error: {
    code: string,  // e.g., "PATIENT_NOT_FOUND", "FHIR_SERVER_UNREACHABLE"
    message: string,
    details?: string
  }
}
```

The TypeScript interface should model these shapes with `success: boolean` as the discriminator. [Source: architecture.md ADR-005]

### NFR Coverage

**NFR-004 (Code Separation):** This story establishes the frontend as an independent project with its own directory, dependency management (package.json), and start command (`ng serve`). The backend is completely separate. [Source: prd.md#NFR-004, architecture.md ADR-006]

**NFR-005 (Browser Compatibility):** Angular 18+ supports current Chrome and Firefox. No special polyfills are needed for modern browser features. [Source: prd.md#NFR-005]

**NFR-003 (Usability for Live Demo):** The proxy configuration and session management set up the infrastructure for the one-click workflow required in later stories. [Source: prd.md#NFR-003]

### Naming Conventions (ADR-006)

- **Files:** kebab-case (e.g., `api.service.ts`, `session.service.ts`, `api-response.model.ts`)
- **Classes:** PascalCase (e.g., `ApiService`, `SessionService`, `ApiResponse`)
- **Component selectors:** `app-{name}` (not used in this story, but established for consistency)
- **Directory structure:** `services/` for services, `models/` for interfaces/types

[Source: architecture.md ADR-006]

### Verification

To verify the proxy works, start both servers:
1. Backend: `uvicorn main:app --reload` (port 8000)
2. Frontend: `ng serve` (port 4200)
3. In the browser console, test: `fetch('/api/patients').then(r => r.json()).then(console.log)`
4. Expected: JSON response from the backend with the response envelope shape

If the proxy is not working, check:
- `angular.json` has `"proxyConfig": "proxy.conf.json"` under serve options
- Backend is running on port 8000
- Backend CORS middleware allows `http://localhost:4200`

### Strategy

**Unit tests:** Focus on SessionService and ApiService logic, not HTTP interactions.

**SessionService:**
- Test that `getSessionId()` returns a valid UUID string
- Test that the session_id is consistent across multiple calls (does not regenerate)

**ApiService:**
- Mock HttpClient using Angular's `HttpClientTestingModule`
- Test that each stub method constructs the correct URL and returns an Observable
- Verify that POST methods include the session_id query parameter (inject a mock SessionService)

**ApiResponse model:**
- No test needed (TypeScript interface, no runtime logic)

**Integration test (manual):**
- Start backend on port 8000 (verify GET /api/patients returns a valid response)
- Start frontend with `ng serve`
- Open browser console, call `fetch('/api/patients')` and verify the response is proxied correctly (should return the backend's JSON, not a CORS error)

**No e2e tests for this story** — scaffold only, no user-facing features yet.

### Edge Cases

- **Proxy misconfiguration:** If proxy.conf.json path is wrong in angular.json, requests to `/api/*` will 404. Verify the path is correct relative to the workspace root.
- **UUID compatibility:** `crypto.randomUUID()` requires a secure context (https or localhost). Since this is localhost-only, it will work. If deploying elsewhere, consider the `uuid` package as a fallback.
- **Tailwind/Material CSS conflicts:** Tailwind's reset can interfere with Material's styles. If buttons or cards render incorrectly, inspect the CSS and scope Tailwind's base import or use a Tailwind preset that minimizes base resets.
