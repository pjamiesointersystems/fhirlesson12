# 4.1: Patient List Component

**Story ID:** 4.1
**Epic:** 4 — Patient Management UI
**Slug:** patient-list
**Status:** ready-for-dev

---

## Story

**As an** instructor
**I want** to see all edge gateway patients displayed in a Material table with click-to-select
**So that** I can choose a patient to demo FHIR operations to learners

---

## Acceptance Criteria — LOCKED

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. **Patient list renders on app load:** Given the app is loaded and the backend is running, when the patient list panel renders, then all 5 patients from patients.txt are displayed with name and identifier visible.

2. **Table uses Angular Material:** Given the patient list is displayed, when the instructor views the component, then it uses MatTableModule with at least two columns: name and identifier.

3. **Click-to-select behavior:** Given the patient list is displayed, when the instructor clicks on a patient row, then the row is visually highlighted and a selection event is emitted containing the patient identifier.

4. **Empty state handling:** Given the backend returns an empty patient list, when the component renders, then a message "No patients available" is displayed instead of an empty table.

5. **Error handling:** Given the backend is unreachable or returns an error response, when the component attempts to load patients, then an error message is displayed in place of the table.

6. **Response time:** Given the backend is running, when the component requests patient data, then the data loads and displays within 2 seconds [Source: prd.md#NFR-001].

## Dev Notes — LOCKED

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

**Architecture:**

This component is part of Epic 4 (Patient Management UI) and implements FR-001 [Source: prd.md#FR-001]. It lives in `frontend/src/app/components/patient-list/` per ADR-006 naming conventions [Source: architecture.md#ADR-006].

**Data source:**

The component calls `ApiService.getPatients()` which hits `GET /api/patients` [Source: architecture.md#6-api-specifications]. The API returns all patients loaded from `patients.txt` at backend startup [Source: sharding-context.md#Existing Python Code Being Wrapped]. Expected response:

```json
{
  "success": true,
  "data": {
    "patients": [
      {"name": "Mary Johnson", "identifier": "356-444-9972"},
      ...
    ]
  }
}
```

[Source: architecture.md#6-api-specifications, ADR-005]

**UI requirements:**

- Use Angular Material `MatTableModule` for the table display [Source: prd.md#FR-001, AC#2, architecture.md#ADR-006].
- Display columns: name (full name) and identifier (e.g., "356-444-9972") [Source: prd.md#FR-001].
- The PRD acceptance criteria state "all 5 patients from patients.txt" [Source: prd.md#FR-001]. The count is determined by the backend; the UI displays whatever is returned.
- Row click must highlight the row visually and emit the patient identifier for consumption by parent/sibling components [Source: prd.md#FR-001, AC "instructor clicks a patient row"].

**Selection event:**

The component must emit or set a shared state value when a row is clicked. Options:
- @Output EventEmitter (if PatientListComponent is nested in a parent)
- Shared service holding selected patient identifier [Inference — architecture does not mandate which approach]

The consuming component is likely PatientDetailComponent (story 4.2) which needs to know which patient was selected [Source: epics.md#Epic 4 dependencies].

**Error handling:**

Follow ADR-005 error envelope [Source: architecture.md#ADR-005]. The ApiService returns `{success: false, error: {code, message, details}}` on failure. Display `error.message` to the user. Common error codes from ADR-005: `INTERNAL_ERROR`, `FHIR_SERVER_UNREACHABLE` (though patient list does not call FHIR server directly) [Source: architecture.md#ADR-005].

**Performance:**

NFR-001 requires API responses < 2 seconds [Source: prd.md#NFR-001, architecture.md#NFR-001]. The patient list endpoint reads from memory (patients loaded at backend startup), so response time should be sub-second [Inference].

**Styling:**

Use Tailwind utility classes for layout/spacing and Angular Material theming for the table [Source: architecture.md#ADR-006]. No custom CSS classes unless Tailwind utilities are insufficient [Source: architecture.md#ADR-006].

**File paths:**

Component files:
- `frontend/src/app/components/patient-list/patient-list.component.ts`
- `frontend/src/app/components/patient-list/patient-list.component.html`
- `frontend/src/app/components/patient-list/patient-list.component.css`

Model file:
- `frontend/src/app/models/patient.model.ts` (shared with PatientDetailComponent)

Selector: `app-patient-list` per ADR-006 [Source: architecture.md#ADR-006].

**Integration:**

This component is consumed by AppComponent or a parent dashboard container component created in story 3.2 (dashboard-layout) [Source: epics.md#Epic 3, story 3.2]. The parent will render `<app-patient-list>` in the Patients workflow section [Source: prd.md#FR-013, architecture.md#4-component-design].

**Dependencies (blocked by):**

- Story 1.2 (patient-endpoints): provides `GET /api/patients` [Source: epics.md#Epic 4 dependencies]
- Story 3.2 (dashboard-layout): provides the dashboard shell where this component is placed [Source: epics.md#Epic 4 dependencies]

**Blocks:**

- Story 4.2 (patient-detail): needs patient selection from this component [Source: epics.md#Epic 4 dependencies]
- Epic 5 stories: observation generation requires a selected patient [Source: epics.md#Epic 5 dependencies]

## Testing — LOCKED

<!-- LOCKED. External dev tools must not edit Testing. -->

**Strategy:**

Unit test the component in isolation with a mocked ApiService. Integration test the component with a running backend.

**Unit tests (PatientListComponent.spec.ts):**

1. **Successful patient list load (AC #1, #2):**
   - Mock ApiService.getPatients() to return `{success: true, data: {patients: [{name: "Test", identifier: "123"}]}}`
   - Verify component populates `patients` array
   - Verify MatTable renders with correct columns and data

2. **Click-to-select emits identifier (AC #3):**
   - Render component with mock data
   - Simulate click on first row
   - Verify selection event emitted with correct identifier
   - Verify visual highlight applied (selected CSS class or MatTable selection state)

3. **Empty state handling (AC #4):**
   - Mock ApiService.getPatients() to return `{success: true, data: {patients: []}}`
   - Verify "No patients available" message is displayed
   - Verify table is not rendered

4. **Error handling (AC #5):**
   - Mock ApiService.getPatients() to return `{success: false, error: {code: "INTERNAL_ERROR", message: "Something went wrong"}}`
   - Verify error message "Something went wrong" is displayed
   - Verify table is not rendered

5. **ngOnInit loads data (AC #1):**
   - Instantiate component
   - Verify ApiService.getPatients() was called exactly once
   - Verify subscription is established

**Integration tests (e2e or manual):**

1. **Full lifecycle (AC #1, #2, #3, #6):**
   - Start backend with patients.txt containing 5 patients
   - Load Angular app
   - Verify patient list displays 5 rows with name and identifier
   - Click a row
   - Verify row is highlighted
   - Verify patient detail panel (story 4.2) updates to show selected patient
   - Verify load time < 2 seconds from page load to data displayed

2. **Backend error scenario (AC #5):**
   - Stop backend or misconfigure API endpoint
   - Load Angular app
   - Verify error message is displayed in patient list panel

**Edge cases:**

- Patient with missing name or identifier fields [Inference — backend should validate, but frontend should not crash]
- Very long patient name or identifier (verify table layout does not break)
- Rapid clicking on multiple rows (verify selection state updates correctly)

**Fixtures:**

- Mock patient data: `[{name: "Alice", identifier: "111-222-3333"}, {name: "Bob", identifier: "444-555-6666"}]`
- Mock error response: `{success: false, error: {code: "INTERNAL_ERROR", message: "Test error"}}`
