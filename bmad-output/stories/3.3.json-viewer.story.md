# 3.3: Build Shared JsonViewerComponent with Syntax Highlighting

**Story ID:** 3.3
**Epic:** 3 — Angular App Shell & Dashboard Layout
**Slug:** json-viewer
**Status:** ready-for-dev

---

## Story

**As an** instructor
**I want** a reusable JsonViewerComponent that displays FHIR JSON with syntax highlighting in a scrollable panel
**so that** learners can easily read Patient, Observation, Bundle, and server response JSON throughout the demo.

---

## Acceptance Criteria — LOCKED

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. A `JsonViewerComponent` exists at `frontend/src/app/components/json-viewer/` (generated with Angular CLI).
2. The component accepts an `@Input() jsonData: any` property (accepts any JSON-serializable object or string).
3. The component renders the JSON with indentation (pretty-printed) inside a scrollable container.
4. JSON syntax highlighting is applied: keys, string values, numbers, booleans, and null are visually distinct (color-coded).
5. If `jsonData` is null or undefined, the component displays a placeholder message: "No JSON data available".
6. The component is styled with Tailwind utility classes for padding, background color, border, and scrolling (`overflow-auto`, `max-h-96` or similar).
7. The component can be used in any other component by importing it and passing JSON via the `jsonData` input.

### Syntax Highlighting Strategy

You have three implementation options:

**Option A: ngx-json-viewer (recommended for speed)**
- Pros: Zero-config, lightweight (<10 KB), handles syntax highlighting automatically
- Cons: External dependency
- Install: `npm install ngx-json-viewer`
- Usage: `<ngx-json-viewer [json]="jsonData"></ngx-json-viewer>`
- This is the fastest path to meeting AC #4. [Inference]

**Option B: highlight.js or prism.js**
- Pros: Powerful, supports many languages, widely used
- Cons: Larger bundle size, requires configuration for JSON language, may be overkill for JSON-only use case
- If using `highlight.js`, you need to manually convert JSON to HTML and apply `hljs` classes
- Not recommended unless you anticipate syntax highlighting for other formats (XML, YAML) later. [Inference]

**Option C: Custom regex-based highlighter**
- Pros: No dependencies, full control, minimal bundle size
- Cons: More code to write and test
- Implementation: Use regex to match JSON tokens (`/"[^"]*":`, `/\b\d+\b/`, `/\btrue|false|null\b/`, etc.) and wrap in `<span class="json-key">` etc.
- Only choose this if bundle size is critical and you want to avoid any dependencies. [Inference]

**Recommendation:** Use **Option A (ngx-json-viewer)** for this story. It's the fastest, meets all ACs, and the bundle size impact is negligible for a local teaching tool. [Inference]

If you choose Option C (custom highlighter), you will need to:
1. Create a pipe or method that returns HTML (use `DomSanitizer` to mark it as safe)
2. Define CSS classes for each token type (key, string, number, boolean, null)
3. Apply the pipe in the template: `<div [innerHTML]="jsonData | jsonHighlight"></div>`

### Input Handling (AC #2, #5)

The `@Input() jsonData: any` property should accept:
- A JavaScript object (will be stringified)
- A JSON string (will be parsed and re-stringified for formatting, or displayed as-is if pre-formatted)
- `null` or `undefined` (show placeholder message)

**Implementation:**
```typescript
@Input() jsonData: any;

get formattedJson(): string {
  if (!this.jsonData) {
    return ''; // Template will show placeholder
  }
  if (typeof this.jsonData === 'string') {
    try {
      // If it's a JSON string, parse and re-format
      return JSON.stringify(JSON.parse(this.jsonData), null, 2);
    } catch {
      // If parse fails, assume it's already formatted and return as-is
      return this.jsonData;
    }
  }
  // If it's an object, stringify it
  return JSON.stringify(this.jsonData, null, 2);
}
```

### Styling (ADR-006, AC #6)

Use Tailwind utility classes for the container:
- `p-4`: padding inside the box
- `bg-gray-50`: light gray background for contrast
- `border border-gray-300`: subtle border
- `rounded`: rounded corners for polish
- `overflow-auto`: scrollbars appear if content exceeds max height
- `max-h-96`: maximum height of 24rem (~384px) before scrolling

If you want a fixed height instead of max height, use `h-96` instead of `max-h-96`. [Inference]

**Font:** Use a monospace font for JSON readability. Tailwind's `font-mono` utility or inline style `font-family: monospace` will work. [Inference]

### Strategy

**Unit tests:**
- Test the component class in isolation (no rendering)
- Mock the `@Input() jsonData` property with various inputs:
  - Test case 1: `jsonData = { foo: "bar" }` → `formattedJson` returns `"{\n  \"foo\": \"bar\"\n}"`
  - Test case 2: `jsonData = null` → component shows placeholder text
  - Test case 3: `jsonData = undefined` → component shows placeholder text
  - Test case 4: `jsonData = '{"foo":"bar"}'` (string) → formatted output is identical to case 1
  - Test case 5: `jsonData = 'invalid json{'` (malformed string) → component handles gracefully (either shows raw string or an error message)

**Component rendering tests:**
- Use Angular's `ComponentFixture` to test the rendered output
- Test case 1: Verify placeholder message appears when `jsonData` is null
- Test case 2: Verify formatted JSON is rendered when `jsonData` is an object
- Test case 3: Verify syntax highlighting classes are applied (check for `.json-key`, `.json-string`, etc. in the DOM, if using custom highlighter; if using `ngx-json-viewer`, just verify the component renders)

**Visual verification (manual):**
- Test with a small JSON object (5-10 lines) — verify colors are distinct and indentation is correct
- Test with a large JSON object (>100 lines) — verify scrollbar appears and scrolling works
- Test in Chrome and Firefox

**No e2e tests** — component is non-interactive.

### Edge Cases

- **Circular references:** If `jsonData` contains circular references, `JSON.stringify` will throw an error. Wrap in try/catch and display an error message: "Cannot display JSON: circular reference detected". [Inference]
- **Very large JSON (>1 MB):** Syntax highlighting may cause performance issues. If this becomes a problem in demo rehearsal, consider disabling highlighting for JSON payloads above a size threshold (e.g., 10,000 lines). Not expected in this app, but good to note. [Inference]
- **Empty object/array:** `jsonData = {}` or `[]` should display as `"{}"` or `"[]"`, not the placeholder message. Verify `if (!this.jsonData)` check distinguishes between `null/undefined` and empty object. Use `if (this.jsonData == null)` instead of `if (!this.jsonData)`. [Inference]
