# 6.1: Add Post Bundle Button with Loading State

**Story ID:** 6.1
**Epic:** 6 — Server Submission & Results UI
**Slug:** post-bundle-ui
**Status:** ready-for-dev

---

## Story

**As an** instructor
**I want** to post the constructed bundle to the FHIR server with a single button click
**So that** learners can see the server submission step in the demo lifecycle

---

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Given a bundle has been built, when the BundlePanelComponent renders, then a "Post Bundle" button is displayed below the bundle JSON preview
2. Given the "Post Bundle" button is visible, when the instructor clicks it, then the button shows a loading state (spinner + disabled state) and calls ApiService.postBundle() with session_id and patient identifier
3. Given the bundle post request is in flight, when the instructor looks at the UI, then the "Post Bundle" button remains disabled with the loading indicator until the response arrives
4. Given the FHIR server returns a successful response, when the post completes, then the button returns to its normal enabled state and the ResultsPanelComponent receives the server response data
5. Given the FHIR server returns an error or is unreachable, when the post fails, then the button returns to its enabled state and an error message is displayed in the BundlePanelComponent or ResultsPanelComponent
6. Given no bundle has been built yet, when the BundlePanelComponent renders, then the "Post Bundle" button is hidden or disabled

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

**This story extends the BundlePanelComponent created in story 5.2** [Inference]. It is a **shared/contended scope** with 5.2 — if 5.2 is in progress or not yet complete, this story must wait (blocked-by dependency enforced).

### Architecture Context

The BundlePanelComponent is part of the Observation & Bundle UI workflow stage. [Source: architecture.md#4-component-design — "BundlePanelComponent: Provides 'Build Bundle' button, 'Post Bundle' button"]

This story adds the "Post Bundle" button, which triggers the final step in the FHIR bundle demo lifecycle: posting the bundle to the InterSystems FHIR server. [Source: prd.md#FR-008 — "The system posts the constructed bundle to the local FHIR server and displays the server response"]

### Functional Requirements Coverage

**FR-008: Post Bundle to FHIR Server — MUST** [Source: prd.md#FR-008]
- AC 1 requires: "Given a bundle has been constructed, when the instructor clicks 'Post Bundle,' then the bundle is sent to the FHIR server"
- AC 2 requires: "Given the server returns 200/201, then the response JSON is displayed including assigned FHIR IDs for each resource"
- AC 3 requires: "Given the server returns an error, then the status code and error message are displayed"

This story satisfies the *button click and submission* part of FR-008. The *response display* part is covered by story 6.2 (ResultsPanelComponent). [Inference]

### API Contract

The `POST /api/bundles/post` endpoint is implemented in Epic 2 story 2.3. [Source: architecture.md#6-api-specifications — "POST /api/bundles/post"]

**Request body:**
```json
{
  "session_id": "uuid",
  "identifier": "356-444-9972"
}
```

**Success response:**
```json
{
  "success": true,
  "data": {
    "patient_id": "742",
    "observation_ids": ["743", "744", "745", ...],
    "bundle_type": "transaction",
    "server_response": { ... }
  },
  "message": "Bundle posted successfully — 101 resources created"
}
```
[Source: architecture.md#6-api-specifications — POST /api/bundles/post response]

**Error response:**
```json
{
  "success": false,
  "error": {
    "code": "NO_BUNDLE" | "FHIR_SERVER_UNREACHABLE" | "FHIR_SERVER_ERROR",
    "message": "...",
    "details": "..."
  }
}
```
[Source: architecture.md#ADR-005 — standardized error envelope]

### UI/UX Guidance

The button must have a clear loading state to signal that a network operation is in progress. Use Angular Material's `mat-button` with `[disabled]` binding and a `mat-spinner` icon when posting. [Source: architecture.md#ADR-006 — "Angular Material components used for buttons"]

The loading state is critical for NFR-003 (Usability for Live Demo): the instructor needs immediate visual feedback when the button is clicked, especially if the FHIR server is slow or unresponsive. [Source: prd.md#NFR-003]

If the bundle has not been built yet (the `buildBundle()` method in BundlePanelComponent has not been called successfully), the "Post Bundle" button should be hidden or disabled to prevent posting a non-existent bundle. [Inference — enforces logical workflow order]

### Error Handling

All errors returned by the backend must be displayed in the UI per NFR-006: "Every error scenario produces a visible message in the relevant dashboard panel." [Source: prd.md#NFR-006]

Possible error codes from `/api/bundles/post`: [Source: architecture.md#6-api-specifications]
- `NO_BUNDLE` — buildBundle() was not called or failed
- `FHIR_SERVER_UNREACHABLE` — FHIR server is down or network issue
- `FHIR_SERVER_ERROR` — FHIR server returned 4xx/5xx

Display the error code and message in a Material alert/banner component within the BundlePanelComponent, or pass it to the ResultsPanelComponent for display. [Inference]

### State Management

The component needs to track:
- `bundleBuilt: boolean` — whether buildBundle() has succeeded
- `isPosting: boolean` — whether postBundle() is in flight

These flags control button visibility/disabled state and loading indicator rendering. [Inference]

The session_id and patient identifier are retrieved from SessionService (session_id) and from the parent component or shared service (identifier). The BundlePanelComponent likely receives the patient identifier as an `@Input()` or subscribes to a selection service. [Inference — consistent with Angular patterns]

### Session Flow

The workflow order enforced by button state: [Inference]
1. Patient selected (Epic 4)
2. Observations generated (Epic 5, story 5.1)
3. Bundle built (Epic 5, story 5.2) → `bundleBuilt = true`
4. **Post Bundle button becomes enabled** (this story)
5. Instructor clicks Post → `isPosting = true` → API call → `isPosting = false` + result emitted
6. ResultsPanelComponent displays result (story 6.2)

### Integration Points

- **ApiService**: Add `postBundle()` method. The ApiService is created in Epic 3 (story 3.1). [Source: architecture.md#4-component-design — "ApiService: Centralized HTTP client"]
- **SessionService**: Provides session_id. Created in Epic 3 (story 3.1).
- **ResultsPanelComponent**: Receives the post result. Built in story 6.2. Communication can be via `@Output()` event, shared service, or subject/observable. [Inference]

### Styling and Conventions

Follow ADR-006 naming conventions: [Source: architecture.md#ADR-006]
- Component file: `bundle-panel.component.ts` (already exists from 5.2)
- Template: `bundle-panel.component.html`
- Use Tailwind utility classes for layout and spacing
- Use Angular Material `mat-button`, `mat-spinner`, and `mat-alert` (or similar)

Follow ADR-007 proxy configuration: all API calls use relative paths `/api/bundles/post`. [Source: architecture.md#ADR-007]

### Non-Functional Requirements

**NFR-001: API Response Time** — Bundle posting may take longer than other endpoints (up to 10 seconds for 100 observations) because it depends on the FHIR server. The loading indicator is essential to show the operation is in progress. [Source: prd.md#NFR-001]

**NFR-006: Error Visibility** — All errors must surface in the UI. Test with FHIR server down, with invalid bundle, and with server returning 5xx to ensure all error paths display messages. [Source: prd.md#NFR-006]

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

### Test Strategy

This story involves UI state management (loading flag), HTTP integration (ApiService), and error handling (envelope parsing). Testing covers:
- **Unit tests** for component logic (button state, method calls)
- **Integration tests** for ApiService.postBundle() (mock HttpClient)
- **Manual tests** for end-to-end UX (loading state, error display)

### Unit Tests (BundlePanelComponent)

**Test: "Post Bundle button is hidden when no bundle is built"**
- Arrange: Set `bundleBuilt = false`
- Act: Render component
- Assert: "Post Bundle" button is not visible or is disabled

**Test: "Post Bundle button is visible and enabled when bundle is built"**
- Arrange: Set `bundleBuilt = true`, `isPosting = false`
- Act: Render component
- Assert: "Post Bundle" button is visible and enabled

**Test: "Post Bundle button is disabled during posting"**
- Arrange: Set `bundleBuilt = true`, `isPosting = true`
- Act: Render component
- Assert: "Post Bundle" button is disabled and shows spinner

**Test: "postBundle() sets isPosting flag and calls ApiService"**
- Arrange: Spy on ApiService.postBundle(), mock return Observable
- Act: Call component.postBundle()
- Assert: `isPosting` is set to true, ApiService.postBundle() called with correct session_id and identifier

**Test: "postBundle() handles success response"**
- Arrange: Mock ApiService.postBundle() to return success envelope
- Act: Call component.postBundle() and complete observable
- Assert: `isPosting` set to false, result emitted to output or service, no error message displayed

**Test: "postBundle() handles error response"**
- Arrange: Mock ApiService.postBundle() to return error envelope (code: FHIR_SERVER_UNREACHABLE)
- Act: Call component.postBundle() and complete observable
- Assert: `isPosting` set to false, error message displayed in template

### Integration Tests (ApiService)

**Test: "postBundle() sends POST request to /api/bundles/post"**
- Arrange: Mock HttpClient, inject ApiService
- Act: Call ApiService.postBundle(sessionId, identifier)
- Assert: HttpClient.post() called with `/api/bundles/post`, body contains session_id and identifier

**Test: "postBundle() returns parsed response envelope"**
- Arrange: Mock HttpClient.post() to return success envelope
- Act: Call ApiService.postBundle()
- Assert: Observable emits parsed data with patient_id and observation_ids

**Test: "postBundle() returns error envelope on failure"**
- Arrange: Mock HttpClient.post() to return error envelope
- Act: Call ApiService.postBundle()
- Assert: Observable emits error object with code and message

### Edge Cases to Test

1. **FHIR server unreachable**: Mock HttpClient to return `FHIR_SERVER_UNREACHABLE` error — verify error displayed in UI
2. **NO_BUNDLE error**: Mock backend returning `NO_BUNDLE` — verify error message says bundle must be built first
3. **Rapid double-click**: Click "Post Bundle" twice quickly — verify `isPosting` flag prevents second call
4. **Large bundle (100+ observations)**: Verify loading state persists for slow requests (manual test with real backend)

### Verification Approach

- Run Angular unit tests with `ng test` — all component and service tests pass
- Manual walkthrough:
  1. Load app, select patient, generate observations, build bundle
  2. Verify "Post Bundle" button appears and is enabled
  3. Click "Post Bundle" — verify spinner appears and button is disabled
  4. Wait for response — verify button returns to enabled state and result is passed to ResultsPanelComponent
  5. Simulate FHIR server down (stop FHIR server) — verify error message displayed
- No test code is written in this story file — tests are implemented in the codebase. [Inference]
