# 1.1: FastAPI Project Scaffold

**Story ID:** 1.1
**Epic:** 1 — Backend API Foundation
**Slug:** fastapi-scaffold
**Status:** ready-for-dev

## Story

**As a** backend developer
**I want** a FastAPI project scaffold with CORS, environment configuration, response envelope, and session state management
**So that** all subsequent API endpoints have a consistent foundation for error handling, state management, and frontend integration.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. FastAPI application starts successfully with `uvicorn main:app --reload` on port 8000.
2. CORS middleware is configured to allow requests from `http://localhost:4200`.
3. Environment variables (`FHIR_SERVER_URL`, `FHIR_SERVER_USER`, `FHIR_SERVER_PASS`) are loaded with defaults matching the InterSystems FHIR server configuration.
4. A standardized response envelope is implemented for all API responses with `success`, `data`, `message`, and `error` fields.
5. Session state management is implemented with a Python dict keyed by `session_id` for storing per-session workflow data.
6. Project dependencies are declared in `requirements.txt` or `pyproject.toml` with pinned versions for FastAPI, uvicorn, fhir.resources 6.1.0, and pydantic <2.0.
7. A health-check endpoint (`GET /api/health`) returns a success response confirming the API is running.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

### Architecture Pattern
[Source: architecture.md#2-architecture-pattern]
This story implements the backend tier of the two-tier Client-Server (SPA + API) architecture. The FastAPI backend will expose REST endpoints consumed by the Angular frontend. The backend wraps existing FHIR logic from `patients.py`, `observation.py`, `batchbundle.py`, and `transactionbundle.py`.

### CORS Configuration
[Source: architecture.md#ADR-007]
**ADR-007: Angular proxy for dev, CORS for fallback**. Configure FastAPI CORS middleware to allow `http://localhost:4200` as an origin. The Angular dev server will use `proxy.conf.json` to forward `/api/*` requests to port 8000, but CORS provides fallback for cases where the proxy isn't used. Use `fastapi.middleware.cors.CORSMiddleware` with `allow_origins=["http://localhost:4200"]`, `allow_credentials=True`, `allow_methods=["*"]`, `allow_headers=["*"]`.

### Environment Configuration
[Source: architecture.md#ADR-003]
**ADR-003: Backend-only FHIR server credentials**. FHIR server URL and credentials must NEVER appear in frontend code or API responses. Backend reads from environment variables with defaults:
- `FHIR_SERVER_URL=http://127.0.0.1:8080/csp/healthshare/demo/fhir/r4`
- `FHIR_SERVER_USER=_System`
- `FHIR_SERVER_PASS=ISCDEMO`

Use Python `os.getenv()` or a config class. These defaults match the InterSystems HealthShare FHIR server used in training.

### Response Envelope
[Source: architecture.md#ADR-005]
**ADR-005: Standardized error response envelope**. All API responses must use a consistent shape to satisfy NFR-006 (error visibility). Define two Pydantic models in `models/responses.py`:

**Success response:**
```python
{
  "success": True,
  "data": {...},
  "message": "Optional message"
}
```

**Error response:**
```python
{
  "success": False,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable message",
    "details": "Optional technical details"
  }
}
```

Error codes (uppercase snake_case): `PATIENT_NOT_FOUND`, `FILE_NOT_FOUND`, `FHIR_SERVER_UNREACHABLE`, `FHIR_SERVER_ERROR`, `INVALID_INPUT`, `NO_OBSERVATIONS`, `NO_BUNDLE`, `INTERNAL_ERROR`.

[Source: prd.md#NFR-006]
**NFR-006: Error Visibility** — all errors must be visible in the UI. The response envelope enables the frontend to reliably detect and display errors.

### Session State Management
[Source: architecture.md#ADR-004]
**ADR-004: Server-side session state with session ID**. The backend holds workflow state (generated observations, constructed bundles) in memory. The frontend sends a `session_id` (UUID) with each request. Backend uses this ID to look up session-specific data.

[Source: architecture.md#ADR-002]
**ADR-002: In-memory session state, no database**. Use a Python dict in memory, keyed by `session_id`. No persistence required — demo state is transient.

Structure (per `architecture.md#5-data-model`):
- `session_id` (UUID, key)
- `selected_patient` (string, optional) — patient identifier
- `observations` (dict: identifier → list of HeartRateObservation)
- `bundle` (Bundle, optional)
- `bundle_type` (string, optional) — "batch" or "transaction"
- `post_result` (dict, optional) — server response with assigned IDs

Implement in `backend/state.py`.

### Naming Conventions
[Source: architecture.md#ADR-006]
**ADR-006: Naming and coding conventions** — Python backend uses snake_case for variables/functions/files, PascalCase for classes. Routers in `routers/`, services in `services/`, models in `models/`. API paths lowercase with kebab-case for multi-word segments (e.g., `/api/observations/from-file`). JSON keys snake_case.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

**Strategy:** Foundational infrastructure — focus on smoke testing and integration verification.

**What to verify:**
1. FastAPI app starts successfully (AC #1)
2. CORS headers present in responses (AC #2)
3. Environment variables load with correct defaults (AC #3)
4. Response envelope models serialize/deserialize correctly (AC #4)
5. Session state can be created and retrieved (AC #5)
6. Health-check endpoint returns expected envelope (AC #7)

**Test types:**
- **Manual smoke test:** Start uvicorn, call health-check endpoint with curl
- **Unit tests:** (optional) Test config loading, session state get/create functions, response model instantiation
- **Integration test:** Call health-check from localhost:4200 origin, verify CORS headers

**Scenarios:**
- **Happy path:** Start API, call `/api/health`, receive `{"success": true, ...}`
- **CORS:** OPTIONS request from localhost:4200 origin receives `Access-Control-Allow-Origin` header
- **Config defaults:** No env vars set → config loads InterSystems defaults

**Edge cases:**
- Missing env var → falls back to default (not an error)
- Invalid session_id in future requests → returns error (covered in subsequent stories)

**No test code or coverage required in this story.** Manual verification is sufficient for scaffold setup. Future stories will add endpoint-specific tests.
