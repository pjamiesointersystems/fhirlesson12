# 5.1: Observation Panel Component

**Story ID:** 5.1
**Epic:** 5 — Observation & Bundle UI
**Slug:** observation-panel
**Status:** ready-for-dev

---

## Story

**As an** instructor
**I want** to generate heart rate observations for a selected patient using either file-based data or synthetic generation, with count display and sample JSON preview
**So that** I can demonstrate how clinical observations are created and show learners the FHIR Observation resource structure

---

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Given a patient is selected, when I click "Generate from File," then observations are generated from the patient's data file and the observation count is displayed in the observation panel
2. Given a patient is selected, when I enter a count (1-1000) and click "Generate Synthetic," then that many observations are generated and the observation count is displayed
3. Given observations have been generated (either method), then the first two observations are displayed as formatted FHIR JSON in the observation panel using JsonViewerComponent
4. Given the observation generation request fails (file not found, patient not selected, server error), then a clear error message is displayed in the observation panel
5. Given no patient is selected, when the observation panel renders, then it shows a placeholder message indicating a patient must be selected first
6. Given synthetic observation count input is out of range (<1 or >1000), then the system clamps the value and displays the corrected count in the UI

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

### Component Responsibility

ObservationPanelComponent provides the UI for generating heart rate observations from either a file or synthetically. It displays the count of generated observations and shows sample observation JSON using the shared JsonViewerComponent. [Source: architecture.md#4-component-design, ObservationPanelComponent section]

### Functional Requirements Coverage

**FR-003: File-Based Heart Rate Observation Generation** — "Generate from File" button calls POST /api/observations/from-file with the selected patient identifier. The API reads from the patient's heart rate data file (e.g., `3564449972.txt`) and returns a count and sample observations. [Source: prd.md#FR-003]

**FR-004: Synthetic Heart Rate Observation Generation** — "Generate Synthetic" button with a count input (1-1000) calls POST /api/observations/synthetic. The API generates random heart rate values and timestamps. Input validation: values <1 default to 1, values >1000 cap at 1000. [Source: prd.md#FR-004]

The API response for both endpoints follows the standardized envelope (ADR-005) and includes `count` and `sample_observations` (first two observations) in the `data` object. [Source: architecture.md#6-api-specifications, POST /api/observations/from-file, POST /api/observations/synthetic]

### Architecture Constraints

**ADR-001 (REST API):** Component calls ApiService methods that invoke POST /api/observations/from-file and POST /api/observations/synthetic. All responses are JSON. [Source: architecture.md#ADR-001]

**ADR-004 (Session State):** The selected patient identifier is passed to both API endpoints. The backend uses session_id (managed by SessionService) to store generated observations server-side. The component does NOT hold observation state — only displays count and sample JSON returned in the response. [Source: architecture.md#ADR-004]

**ADR-005 (Error Envelope):** Component checks `success` field in API response. On `success: false`, extract `error.message` and display in the panel. Expected error codes: `PATIENT_NOT_FOUND`, `FILE_NOT_FOUND`, `INVALID_INPUT`. [Source: architecture.md#ADR-005]

**ADR-006 (Naming & Styling):** Component file: `observation-panel.component.ts`, selector: `app-observation-panel`. Use Angular Material components (mat-card, mat-button, mat-form-field, mat-input) and Tailwind utility classes for layout. No custom CSS unless Material/Tailwind are insufficient. [Source: architecture.md#ADR-006]

### Data Flow

1. User selects patient in PatientListComponent → parent (AppComponent or shared service) provides `selectedPatientIdentifier` as an @Input or via a shared service
2. User clicks "Generate from File" → component calls `ApiService.generateFromFile(selectedPatientIdentifier)` → backend returns `{ success: true, data: { count: N, sample_observations: [...] } }`
3. Component updates observation count display and passes `sample_observations` array to JsonViewerComponent
4. For synthetic generation: user enters count → component validates/clamps → calls `ApiService.generateSynthetic(selectedPatientIdentifier, count)`

[Inference: AppComponent likely manages patient selection state and passes it down as an @Input, or a shared service emits the selected identifier. Coordinate with Epic 4 (patient-list, patient-detail) implementation.]

### API Integration

**POST /api/observations/from-file**
Request body: `{ session_id, identifier }`
Success response:
```json
{
  "success": true,
  "data": {
    "count": 100,
    "sample_observations": [ {...}, {...} ]
  },
  "message": "Generated 100 observations from file"
}
```
Error response: `{ success: false, error: { code: "FILE_NOT_FOUND", message: "...", details: "..." } }`

**POST /api/observations/synthetic**
Request body: `{ session_id, identifier, count }`
Success response: same structure as from-file
[Source: architecture.md#6-api-specifications]

### UI/UX Notes

- Observation panel should be disabled or show placeholder text when no patient is selected (AC #5) [Source: prd.md#FR-003, FR-004 — "Given a patient is selected"]
- Count input field: use Angular Material `mat-form-field` with type="number", min="1", max="1000". Apply validation in component TypeScript (clamp on blur or button click). [Inference based on Material best practices]
- Sample observations: display using `<app-json-viewer [json]="sampleObservations[0]"></app-json-viewer>` and `<app-json-viewer [json]="sampleObservations[1]"></app-json-viewer>` or loop with *ngFor if JsonViewerComponent supports array input. Confirm JsonViewerComponent API from 3.3 implementation. [Source: architecture.md#4-component-design, JsonViewerComponent]

Mock ApiService responses with success and error scenarios. Mock selected patient identifier as component @Input or service value.

**Integration tests** (e2e or component integration):
- Verify clicking "Generate from File" updates observation count in the DOM
- Verify JsonViewerComponent receives and renders sample observations (check for presence of JSON content in child component)
- Verify error message appears in panel when backend returns FILE_NOT_FOUND

**Edge cases to cover:**
- No patient selected → buttons disabled or error message shown
- File not found for patient → error displayed (AC #4)
- Count = 0 → clamped to 1
- Count = 9999 → clamped to 1000
- Backend unreachable → error envelope with FHIR_SERVER_UNREACHABLE or INTERNAL_ERROR displayed
